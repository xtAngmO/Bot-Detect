# 🎯 Number Sequence Bot (บอทเรียงเลข)

บอทแก้เกม "ตารางเลข" (Schulte grid) อัตโนมัติ — เกมที่มีตัวเลข 1–25 สลับตำแหน่งในตาราง 5×5
แล้วต้องแตะเรียงจากน้อยไปมาก บอทจะ **อ่านค่า "เลขต่อไป" ด้วย OCR → หาตำแหน่งเลขนั้นในตาราง →
วาดวงไฮไลต์ชี้เป้า → คลิกให้อัตโนมัติ** วนจนครบ รองรับเกมที่รันอยู่ใน **LDPlayer** (Android emulator
บน PC) — วิธีเดียวกับที่โปรเจกต์พี่น้อง [`bot_detect_word`](../../../../bot_detect_word) ใช้กับฟีเจอร์
จับคู่การ์ด

## ติดตั้ง (ทำไว้ให้แล้วในเครื่องนี้)

1. ต้องมี **Tesseract OCR** ที่ `C:\Program Files\Tesseract-OCR\tesseract.exe`
   (ถ้ายังไม่มี: <https://github.com/UB-Mannheim/tesseract/wiki>)
2. `.venv/` ถูกสร้างและลง dependency ไว้แล้ว (`PySide6`, `mss`, `pytesseract`, `Pillow`, `keyboard`)
   — ถ้าย้ายเครื่อง/ลบ `.venv` ทิ้ง ให้สร้างใหม่:
   ```powershell
   python -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   ```

## รัน

```powershell
.venv\Scripts\python.exe main.py
```

## ใช้งาน

1. เปิด LDPlayer ให้เกมตารางเลขแสดงอยู่บนจอ
2. กด **👁 แสดงกรอบตาราง** แล้วลากกรอบสีเขียวไปครอบตาราง 5×5 ทั้งก้อน — ลากแถบขอบ = ย้ายกรอบ,
   ลากมุมขวาล่าง (สี่เหลี่ยมฟ้า) = ย่อ/ขยาย บอทจะหารกรอบนี้เป็น 25 ช่องเองอัตโนมัติ
3. กด **👁 แสดงกรอบเลขต่อไป** แล้วลากกรอบสีฟ้าไปครอบตัวเลขในการ์ด "เลขต่อไป" ของเกม (กรอบแค่
   พอดีตัวเลข ไม่ต้องครอบทั้งการ์ด)
4. ปรับ แถว×คอลัมน์ / เลขสูงสุด ถ้าเกมไม่ใช่ 5×5/1–25 (ค่าเริ่มต้นตรงกับสกรีนช็อตที่ใช้ออกแบบ)
5. กด **▶ เริ่มอัตโนมัติ** — บอทจะวนอ่าน-หา-ไฮไลต์-คลิก จนกดครบทุกเลข หรือกด **■ หยุด** /
   แป้น **Esc** (panic key) เพื่อหยุดฉุกเฉินได้ทุกเมื่อ แม้ตอนโฟกัสอยู่หน้าต่างอื่น

ตำแหน่งกรอบ + การตั้งค่าทั้งหมดถูกจำไว้ใน `config.json` ข้างๆ สคริปต์ — เปิดครั้งต่อไปไม่ต้องลากใหม่

## ความปลอดภัย

- **Panic key (Esc)** หยุดได้ทันทีไม่ว่าโฟกัสอยู่หน้าต่างไหน (global hotkey ผ่านไลบรารี `keyboard`
  — บางเครื่องต้องรัน PowerShell แบบ Administrator ถึงจะดักคีย์ข้ามหน้าต่างได้)
- ถ้าหาตำแหน่งเลขเป้าหมายในตารางไม่เจอติดกันเกิน **20 รอบ** บอทจะหยุดเองพร้อมข้อความ error
  (กันวนเปล่าๆ ไม่จบ / กันคลิกมั่วตอนอ่านค่าไม่ได้จริงๆ)
- บอทจะ**ไม่คลิก**ถ้าไม่เจอเลขเป้าหมายในตารางรอบนั้น (ปลอดภัยกว่าคลิกมั่ว) — แค่รอรอบถัดไป

## OCR — ทำไมอ่านเลขแม่นกว่าที่คิด

ก่อน OCR ทุกภาพจะถูก **ตัดให้เหลือแค่ตัวเลข** (ทิ้งทุกอย่างที่แตะขอบภาพ เช่น เส้นขอบกรอบ overlay /
ขอบการ์ด และทิ้งตัวอักษรที่เล็กกว่าตัวเลขหลัก เช่นป้าย "เลขต่อไป") แล้ว **ย่อ/ขยายให้ตัวเลขสูง ~40px**
เสมอ — ขนาดที่ Tesseract อ่านแม่นสุด ไม่ว่าเกมจะแสดงตัวเลขใหญ่แค่ไหน

วัดจริงพบว่า Tesseract โหมด `--psm 8` (คำเดี่ยว) อ่านเลขโดดบางตัวพลาดแบบ "มั่นใจผิด"
(`"1"` → `"4"`, `"11"` → `"411"`) ซึ่งอันตรายเวลาต้องจับคู่ตำแหน่งเซลล์ในตาราง — บอทเลยอ่าน
หลายรอบ: **`psm 6` (บล็อกข้อความ) เป็นหลัก** ที่ความสูง 40 → 32 → 52px เพราะพลาดแบบ "อ่านไม่ออก"
(ปลอดภัย) มากกว่า "มั่นใจผิด" แล้วค่อย **fallback ไป `psm 7` และ `psm 8`** เฉพาะตอนอ่านไม่ออกหรือ
อ่านได้เลขที่เกินช่วงที่เป็นไปได้จริง (ดู `capture.read_number_robust`)

## พิกัดจอ (DPI scaling)

Qt ทำงานเป็น logical px แต่ mss (จับภาพ) และ `SendInput` (คลิก) ใช้ physical px — จอที่ตั้ง scale
เช่น 125% ต้องแปลงก่อน ไม่งั้นจับภาพผิดที่ทั้งก้อน `config.json` เก็บพิกัด Qt (logical) ส่วน
`solver.py` แปลงผ่าน `screenmap.ScreenMap` ก่อนจับภาพ/คลิกทุกครั้ง

## โครงสร้างโค้ด

| ไฟล์          | หน้าที่                                                              |
| ------------- | --------------------------------------------------------------------- |
| `main.py`     | entry point                                                            |
| `app.py`      | หน้าต่างหลัก (PySide6) — ปุ่มควบคุม, การตั้งค่า, log console            |
| `overlay.py`  | กรอบโปร่งใสลาก/ย่อ-ขยายได้ (คลิกทะลุกลาง ด้วย `setMask`) + วงไฮไลต์ชี้เป้า |
| `capture.py`  | จับภาพจอ (mss) + OCR เลข (ตัดเหลือตัวเลข → ปรับสูง 40px → psm 6→7→8)   |
| `screenmap.py`| แปลงพิกัด Qt (logical) ↔ พิกัดจอจริง (physical) ตาม scale ของจอ           |
| `solver.py`   | ลูปแก้เกมอัตโนมัติ — จำตำแหน่งเลข, คลิก, ยืนยันจากกรอบเลขต่อไป (~0.16s/คลิก) |
| `mouse.py`    | คลิกเมาส์ผ่าน ctypes `SendInput`                                       |
| `config.py`   | โมเดลการตั้งค่า + โหลด/เซฟ `config.json`                              |
| `tests/`      | เทสต์แบบ headless (ไม่ต้องมีจอ/เกมจริง) — ดูหัวข้อ "เทสต์" ด้านล่าง        |

## เทสต์

```powershell
.venv\Scripts\python.exe tests\test_ocr.py
.venv\Scripts\python.exe tests\test_grid.py
.venv\Scripts\python.exe tests\test_real_capture.py   # ภาพเกมจริง (tests/fixtures/, จอ 125%)
.venv\Scripts\python.exe tests\test_solver.py         # ลูป solver กับเกมจำลอง
.venv\Scripts\python.exe tests\test_screenmap.py
$env:QT_QPA_PLATFORM = "offscreen"; .venv\Scripts\python.exe tests\test_app_smoke.py
```

เทสต์ `test_app_smoke.py` no-op `Settings.save` ไว้ก่อนเสมอ กัน config.json ของจริงโดนเขียนทับ
(บทเรียนจากโปรเจกต์พี่น้อง `bot_detect_word`)

## ข้อจำกัดที่รู้อยู่แล้ว

- ทดสอบ OCR กับภาพเกมจริงแค่ชุดเดียว (`tests/fixtures/`) บวกฟอนต์จำลอง — ถ้าเกมเปลี่ยนสี/พื้นหลัง
  (เช่นตัวเลขสีอ่อนบนพื้นเข้ม) ต้องปรับ `_INK_THRESHOLD` / ลอจิกหมึกใน `capture.py`
- ยังไม่มีการ build เป็น `.exe` แบบ portable (ต่างจาก `bot_detect_word`) — รันจาก source ผ่าน
  `.venv` เท่านั้น ตอนนี้เน้นให้ใช้งานได้เร็วที่สุดก่อน
